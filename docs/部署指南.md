# 部署指南（Cloudflare Workers + D1 + R2 + Access，家裡 Linux 跑 Dr.Claude）

架構照二胎代書系統：網站與資料在 Cloudflare（免費額度內），家裡的 Linux 只跑 Dr.Claude 服務（runner），來領工作、處理、送回。
家裡主機關機時，紀錄、打勾、提醒都照常，只有 Dr.Claude 暫停（畫面會顯示「家裡的主機好像沒開」，開機後自動補回覆）。

```
手機（PWA）──► doctor.nathantw.com（Worker + D1 + R2）◄── 家裡 Linux：dr-claude-runner（Agent SDK）
                     ▲ Access：只擋 /api/auth/login（Google）與 /api/agent（服務憑證）
```

## 1. 自動部署（一次性）

1. GitHub → `YuLiangLin/family-doctor` → Settings → Secrets and variables → Actions：
   - Secrets：`CLOUDFLARE_API_TOKEN`、`CLOUDFLARE_ACCOUNT_ID`（可以沿用二胎那一組；token 要有 Workers Scripts、D1、Workers Routes（All zones）的 Edit 權限；Cloudflare 上叫 `xingzhong-deploy`）。
   - Variables：`RUNNER` = `self-hosted`（跟二胎共用那台自架 runner；沒設就用 GitHub 的機器）。
     自架 runner 是「每個 repo 各自註冊」的：在 repo 的 Settings → Actions → Runners → New self-hosted runner 照步驟在同一台再裝一個（不同資料夾）。
2. push 到 `main` → Actions 跑檢查 → 套用 migrations → 部署。第一次部署後 `doctor.nathantw.com` 會自動建好 DNS 與憑證（2026-11-05 以前是 `doctor.lottery-wangwang.com`，見 §9）。
3. 這時打開網站會看到「系統尚未設定 Cloudflare Access」：正常，做完 §2 就好（fail closed）。

Google 登入方式在二胎時已經設好（Zero Trust team `nathantw`，Identity provider Google、instant auth），這裡只要新增一個應用程式：

1. Zero Trust → Access controls → Applications → **Add an application → Self-hosted**，名稱 `家庭醫生`。
2. Destinations（Public hostname），兩筆：

   | Domain | Path |
   |---|---|
   | `doctor.nathantw.com` | `api/auth/login` |

   | `doctor.lottery-wangwang.com` | `api/auth/login` |
   | `doctor.lottery-wangwang.com` | `api/agent` |

   （舊網址那兩筆在 §9 搬完、家人都改用新網址後可以刪。）

   其他網址不經過 Access，由 Worker 自己驗（同二胎 §2-13：系統登入憑證一年、每天用就延長）。
3. Login methods：只勾 **Google**、開 **instant authentication**。
4. Policies：
   - `家人`：Action **Allow**，Include → **Emails** → 填家人的 Gmail（`yliang.lin@gmail.com`、Candy 的 Gmail）。
     （第二道關卡在系統裡：設定頁「能登入的帳號」名單，不在名單的人就算過了 Access 也進不來。）
   - `Dr.Claude 服務`：Action **Service Auth**，Include → **Service Token** → §3 建的 token（先建 token 再回來加）。

6. 驗證：無痕視窗開 `https://doctor.nathantw.com/api/me` → 401 JSON「未登入」；首頁按「用 Google 帳號登入」→ 選帳號 → 進到「今天」頁。

## 3. Dr.Claude 服務（家裡的 Linux）

### 3-1. 服務憑證（Cloudflare）

1. Zero Trust → Access controls → Service credentials → Service Tokens → **Create service token**：名稱 `家庭醫生-DrClaude`、期限選不過期（Nathan 2026-11-04 指定，同二胎，不用每年換）。
   複製 **Client ID**（結尾是 `.access`）與 **Client Secret**（只顯示一次）。
2. 回 §2-4 把 Service Auth 政策加上這個 token。
3. Worker 變數：Workers & Pages → `family-doctor` → Settings → Variables and Secrets → Add（類型選 Secret，部署不會清掉）：
   `AGENT_CLIENT_IDS` = `<Client ID>=家裡的主機`。

### 3-2. API key（Anthropic Console）

跟二胎一樣：**不能用 Nathan 個人的 Max 訂閱幫家人跑**（訂閱只給本人用），所以 runner 用 Console 的 API key。

- Console 開一個 workspace `家庭醫生`、設每月花費上限（例如 US$20），在裡面建一把 key。
- 粗估：一般對話（Sonnet）一則約 US$0.01～0.05；讀藥袋（Opus，有照片）一張約 US$0.05～0.2。以 Console 的 Cost 頁為準。
- 每個帳號每天最多問 60 次（Worker 變數 `AI_DAILY_LIMIT` 可調）。

### 3-3. 安裝 runner（一次性，用平常的帳號，不用 root）

```bash
sudo apt install -y git python3-venv
git clone https://github.com/YuLiangLin/family-doctor ~/family-doctor      # 私有 repo：先 gh auth login
cd ~/family-doctor/scripts/dr-claude-runner
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt

mkdir -p ~/.config/dr-claude && touch ~/.config/dr-claude/env && chmod 600 ~/.config/dr-claude/env
# 用 read -rs 貼，不會留在指令紀錄
read -rs V && printf 'FD_ANTHROPIC_API_KEY=%s\n' "$V" >> ~/.config/dr-claude/env
read -rs V && printf 'FD_AGENT_CLIENT_ID=%s\n' "$V" >> ~/.config/dr-claude/env
read -rs V && printf 'FD_AGENT_CLIENT_SECRET=%s\n' "$V" >> ~/.config/dr-claude/env; unset V

.venv/bin/python runner.py --check    # 系統登入（服務憑證）、SDK、API key 全部 ✓
```

變數名稱故意不叫 `ANTHROPIC_API_KEY`：那會讓這台機器上的 Claude Code 改用 API key。其他選填設定（模型、花費上限、逾時）見 `runner.py` 開頭。

試一件：在網站 Dr.Claude 問一句話 → `.venv/bin/python runner.py --once` → 畫面出現回覆。

裝成服務（開機自動跑、沒登入桌面也跑）：

```bash
mkdir -p ~/.config/systemd/user && cp ~/family-doctor/scripts/dr-claude-runner/dr-claude.service ~/.config/systemd/user/
systemctl --user daemon-reload && systemctl --user enable --now dr-claude
sudo loginctl enable-linger "$USER"
journalctl --user -u dr-claude -f       # 紀錄只有工作編號、結果、花費，不記內容
```

**自動更新**（v0.4.1 起）：runner 每 5 分鐘看 GitHub 的 `main` 有沒有新版，有就自己快轉、裝新套件、跑 `test_runner.py`，
測試過了才換新版重新啟動；沒過就退回原本那版、記在 journal。只在 `~/family-doctor` 停在 `main`、沒有改過的檔案時才動。
不要自動更新就在設定檔加 `FD_AUTO_UPDATE=off`。`runner.py --check` 會顯示自動更新能不能用（要能 `git fetch`：`gh auth login`）。

還沒有自動更新的舊版 runner（v0.4.0 以前）要手動更新最後一次：
```bash
cd ~/family-doctor && git pull && scripts/dr-claude-runner/.venv/bin/pip install -r scripts/dr-claude-runner/requirements.txt && systemctl --user restart dr-claude
```

### 3-4. 安全設計

- runner 用長輪詢向系統領工作（`POST /api/agent/jobs/claim?wait=25`），家裡不用開任何對外的 port。
- AI 只能用 runner 提供的工具（記日記、記量測、提看診草稿、查紀錄、設表情）和 Read（只讀這件工作的附圖）；沒有 Bash、不能上網。
  不載入這台機器的 Claude Code 設定（`setting_sources=[]`）。
- 寫進系統的東西由 runner 送、伺服器再檢查一次（家人存在、數值合理）；看診與用藥只會是**草稿**，要人在畫面按「核對後存起來」。
- 工作資料夾（`/tmp/fd-job-*`，有健康資料）每件做完就刪。
- 處理到一半當機：15 分鐘後系統把那件標成失敗，畫面有「再試一次」。

## 6. API token（給 Claude Code 等程式用）

2026-11-05 Nathan 要的：讓 Claude Code（或其他雲端 AI）用 token 進系統查問題、照他的指示記錄。

1. 用 Google 登入 → 設定頁 →「API token」→ 建立：取名字（紀錄上會標「經 API：名字」）、選權限、選期限（最長一年）。
   - **唯讀**：今天、時間軸、家人、看診、用藥、附件。
   - **記日常**：再加記身體狀況、量測、吃藥打勾。適合語音助理。
   - **完整寫入**：再加家人、看診、用藥（直接生效）、上傳附件。
   - 都不能管帳號、建 token、用 Dr.Claude 對話、走 `/api/agent`。
2. token 只顯示一次。Claude Code 雲端：對話標題列的環境選單 → Edit → 環境變數 `FD_API_TOKEN`。新開的對話才讀得到。
3. 呼叫：`Authorization: Bearer <token>`；`scripts/fd-api.sh GET /today`。
4. 不用了、外流了：設定頁按「撤銷」，馬上失效。每一把都看得到上次使用時間。

## 7. 藥品照片（食藥署開放資料「藥品外觀」）

2026-11-05 Nathan 要的：每種藥配上真實照片。資料來源 `https://data.fda.gov.tw/data/opendata/export/42/json`（約 6,400 筆口服藥、多數有照片），使用時標註來源（畫面上有）。

1. **藥品資料**：`.github/workflows/drug-catalog.yml` 每週一台北 03:17 同步到 D1 的 `drug_catalog`。第一次部署後到 Actions →「Drug catalog」→ Run workflow 手動跑一次。
2. **照片**：家裡的 runner 處理（`runner.py` 的 `process_drug_photos`）：有人要看某一款的照片 → 系統排進 `drug_photos` → runner 從食藥署下載原圖（有的 20MB）、
   自動裁到藥丸、縮小（480px 小圖、1200px 整張）→ 傳回系統存 R2。家人的手機只跟我們的網站拿照片，不直接連食藥署。
   - runner 多了 numpy：v0.4.1 起 runner 會自動更新、自己裝（§3-3）；更舊的版本要手動更新一次。
   - `runner.py --check` 會顯示 numpy 有沒有裝好；沒裝也能跑，只是照片不會自動裁切。
   - 家裡主機關機時，新的照片會停在「準備中」（畫面先畫一顆同顏色、同形狀的藥），開機後自動補上。
3. **挑哪一款**：同成分常有好幾家藥廠、長得不一樣。記看診時打藥名會列出最像的幾款（藥名＞成分＞劑量，再看藥袋寫的顏色、劑型），要人點選才算數。
